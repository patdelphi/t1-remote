# T1 Remote Key Mapping 架构与前台设计

## 文档目的

本文确定 Key Mapping 的输入边界、动作模型和前台编辑流程。当前实现面向 T1 遥控区域的 14 个物理按键，配置文件仍使用 `version: 1`，前台输出与运行时一致的 JSON 结构。

## 运行链路

```text
T1 HID 报文
    │
    ├─ COL02/COL03：过滤驱动拦截并进入桥接队列
    └─ COL01：Raw Input 读取，当前仍保留键盘集合边界
    │
    ▼
T1InputDecoder：报文 → 物理按键 down/up
    │
    ▼
MappingEngine：按键状态、长按、双击、按住重复、热加载释放
    │
    ▼
KeyAction：none / key / combo / special / command
    │
    ├─ key/combo/special → Windows SendInput
    ├─ command          → shell=False 启动 argv
    └─ none             → 只观察，不产生系统输出
```

驱动只负责把需要隔离的 T1 原始输入挡在系统默认 HID 行为之外，Python 负责按用户配置生成最终动作。同一个物理按键只从一条输出链路产生动作，避免驱动改写和 SendInput 重复触发。

## 前台信息架构

主前台 `tools/t1_app.py` 负责启动/停止 Mapping 会话，显示驱动状态、租约、事件计数、最近事件和日志。Windows 通知区域图标负责隐藏、恢复和退出；映射编辑器与 Inspector 以独立 Tkinter 进程运行，避免多个 Tk 主循环共享同一个窗口，也避免采集时误改配置。

界面分成三块：

1. 左侧“物理按键”：列出 14 个遥控区域按键，显示当前动作摘要。Air Mouse 标记为暂未纳入本轮映射。
2. 中间“动作类型”：下拉选择动作类型。选择后只显示相关字段，用户不需要直接编辑 JSON。
3. 右侧“动作参数”：根据类型填写参数，并显示预览结果。底部提供“应用到当前按键”“预览动作”“保存配置”“导入”“导出”“重新加载”“恢复默认”。动作类型下方还可以选择按下、长按、双击或按住重复。

窗口顶部显示当前配置文件路径和运行边界提示：COL02/COL03 已有设备级拦截；COL01 的方向、OK、Menu 若改成其他输出，仍需注意原始键盘输入可能同时到达 Windows。

## 用户如何选择映射方式

选择一个物理按键后，在“动作类型”下拉框选择以下四类之一：

| 前台名称 | JSON type | 配置字段 | 适用场景 |
| --- | --- | --- | --- |
| 单键 | `key` | `key` | 输出 A、Enter、方向键、F1 等单个键 |
| 组合键 | `combo` | `key`、`modifiers` | 输出 Alt+Tab、Ctrl+C、Win+D 等 |
| HID 特殊功能 | `special` | `key` | 音量、媒体、浏览器、电源、睡眠等 Windows HID 功能 |
| 命令行 | `command` | `argv` | 启动程序或传递固定参数 |

另有“未映射”选项，对应 `none`。它用于保持观察状态，适合 Power、Voice 和尚未确认的按键。

触发方式也写入动作配置：`press` 表示按下即输出，`long_press` 使用毫秒阈值，`double_click` 使用两次点击的最大间隔，`hold_repeat` 使用重复间隔。旧配置没有 `trigger` 字段时按 `press` 处理。

## 各类型参数规则

### 单键

使用受支持的 Windows 虚拟键名称下拉框，包括字母、数字、方向键、Enter、Esc、空格、删除、Home、Apps 和 F1-F12。保存前会按 `KeyAction` 和 `SendInput` 的同一套规则校验。

### 组合键

选择一个主键，再勾选 Alt、Ctrl、Shift、Win 中的修饰键。修饰键不能重复，至少选择一个。按下时先按修饰键再按主键，释放时按相反顺序释放，防止留下粘键。

### HID 特殊功能

从预置列表中选择 Volume Up、Mute、Media Play/Pause、浏览器导航、Calculator、Power、Sleep、Wake 等功能。前台只显示已实现的预置项，不允许输入未实现的虚拟键名。

### 命令行

填写“程序路径”和“参数”。每行一个参数，编辑器保存为 `argv` 数组，运行时使用 `shell=False` 启动，不解析 Shell 元字符。预览只展示命令，不会启动程序；实际执行发生在映射运行时收到按下事件时。

## 保存与测试流程

1. 选择物理按键和动作类型。
2. 填写参数，点击“应用到当前按键”。输入不完整时保留当前配置并显示错误。
3. 点击“预览动作”确认最终动作。命令行只预览 argv，不执行外部程序。
4. 点击“保存配置”。配置以 UTF-8 BOM、CRLF 和临时文件替换方式写入，保存失败不覆盖旧文件。
5. 使用 `python -m tools.t1_mapping_test --dry-run` 做真实设备链路的无副作用测试；确认输出后再运行实际模式。

“导入”只替换当前编辑会话，仍需点击“保存配置”才会覆盖默认文件；“导出”把当前编辑会话保存到另一个 JSON 文件，适合备份和切换配置。

重新加载配置或运行时热加载时，先释放旧映射的活动按键，再切换新配置，避免修改过程中出现粘键。设备移除、系统睡眠和应用退出也会调用同一释放路径；系统恢复后重新发送桥接心跳并更新驱动状态。

命令行测试入口会轮询配置文件。编辑器保存有效配置后，运行中的会话会自动热加载；非法 JSON 或字段校验失败只记录错误并继续使用上一份有效配置。

## 安全边界

运行时诊断会记录输入总数、忽略输入数、映射事件数、SendInput 事件数、命令启动数和错误数，并保留有限数量的脱敏最近事件。测试入口退出时打印计数和最近记录，便于区分“没有收到报文”“没有匹配映射”和“输出失败”。

- 默认 Power、Voice、Air Mouse 不输出动作。
- 命令行动作使用参数数组，不经过 Shell；配置文件中的程序仍会以当前用户权限启动。
- 配置校验失败时保持旧文件和当前生效配置不变。
- COL02/COL03 的设备级拦截可阻断默认 Consumer/System 行为；COL01 当前未完成设备级区分，键盘面与遥控区域共用字段时不能承诺完全无泄露重映射。
- 未知 Usage 只记录，不自动猜测成按键。

## 本轮开发完成标准

- 14 个物理按键可以逐项选择和查看动作摘要。
- 四类动作和未映射状态可以在界面中配置并保存为现有 JSON 格式。
- 单键、组合键、HID 特殊功能和命令行都能在预览中看到明确结果；长按、双击和按住重复能显示对应参数。
- 非法参数不会写入配置；保存后重新加载结果一致。
- Inspector 能启动映射编辑器，命令行测试入口继续可用。
- 核心编辑逻辑有自动化测试，真实遥控器按键仍需现场验证。

## 后续扩展

长按、双击、按住重复、按键录制、应用限定映射和鼠标动作属于下一阶段。它们需要在现有 `KeyAction` 上增加触发条件和更细的输入证据字段，当前 UI 不提前暴露这些未实现选项。

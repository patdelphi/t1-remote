# T1 遥控区域报文采集范围

## 识别结论

产品图和规格页中的“A 面 12 个按键、2 个侧键”与遥控器外观一致：正面 12 个实体按键，左右侧各一个音量键，共 14 个遥控区域按键。

方向环拆分为 4 个方向键，中心单独作为 OK 键。图片中的 `Air Mouse` 是开启飞鼠功能的按键，采集阶段禁用；Power 由驱动层拦截后在 Python 界面采集。

## 明确排除

- B 面 45 个键盘按键；
- 键盘面的 Fn 组合键；
- 键盘面的方向、Home、Page、Enter 等按键；
- 空中鼠标移动产生的连续 Mouse Report；
- 红外码学习和红外发射报文；
- 2.4G 接收器报文。

`Air Mouse` 不进入本轮按键采集。开启飞鼠后的连续鼠标移动只作为后续功能开发的输入来源，不写入按键夹具。Power 允许进入采集，但必须由驱动层先拦截，避免触发 Windows 电源动作。

## 采集原则

1. 设备连接后先静置，记录无按键状态下的基线报文。
2. 按清单逐个按键，每个按键执行短按 3 次、长按 1 次、快速松开 1 次。
3. 每次只按一个键，方向环的方向和 OK 分开操作。
4. 记录原始 Report、Collection、Usage Page、Usage、按下/释放和时间戳。
5. 未知 Usage 只记录，不自动映射和注入系统按键。
6. 采集文件只保存脱敏后的设备标识和报文，不保存蓝牙地址。

## Inspector 使用方式

在项目根目录打开 PowerShell，运行。程序会打开 Tkinter 窗口，以 `assets/t1-remote-front-clean-v2.png` 遥控器正面产品图为中心排布 14 个采集按钮：

```powershell
& "C:\Python313\python.exe" -m tools.t1_inspector --output "captures\t1-remote-control.json"
```

Inspector 启动后输入按键编号并回车，再只按对应的遥控区域按键。输入 `0` 清除标签，输入 `s` 手动保存，输入 `q` 退出并保存。程序只接受 `VID_620A`、`PID_0407` 的 T1 Raw Input；没有选择物理按键标签时，报文不会写入夹具。

窗口中的表格显示配对后的逻辑操作。保存文件同时保留两层数据：`events` 是每一条原始包，`logical_actions` 是按下/抬起配对后的结果。同一次短按通常包含 2 个原始包，但只计为 1 个逻辑操作。Power 由驱动层拦截后在采集窗口中启用；Air Mouse 继续禁用，避免飞鼠移动干扰。

每条 `events` 记录还会保存可从当前已知布局推导出的 `state`、`usage_page` 和 `usage`。文件中的 `capture_coverage` 摘要按已启用的 13 个实体键统计观测结果；只有每个按键至少出现一次成对的按下+抬起操作时，`complete` 才为 `true`。未知布局仍保存原始包，但不会被判定为完成。

文件中的 `physical_mapping` 是观察表，不会直接覆盖 `config/t1-key-mapping.json`。每个按键会标记为 `confirmed`、`observed`、`missing` 或 `disabled`，同时保留 Collection、Usage、状态和最多 3 条样本报告，便于人工确认后再配置动作。

右侧“后续组件预留”区域会实时显示驱动诊断：附着的 Collection、收到/拦截/转发的报告数量和队列深度。按键无记录时先看这里：`收到=0` 表示驱动没有拿到输入报告，`收到>0` 但表格无记录则继续检查 Python 事件处理。

## 暂定验收标准

- 14 个按键都能找到对应的采集记录，或明确标记为未产生 HID 报文；
- 每个已识别按键能区分按下和释放；
- 重复按键不会被误合并为一次；
- 键盘面按键未被纳入遥控区域夹具；
- Air Mouse 开启飞鼠后的鼠标移动报文及其映射方式；
- Voice 键的 HID 事件与 GATT 音频验证结果分开记录。

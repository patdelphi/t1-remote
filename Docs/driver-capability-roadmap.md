# T1 Windows 驱动能力规划

程序说明：定义 T1RemoteFilter.sys 的长期能力边界、优先级和验收标准。驱动负责设备级输入通道，Python 负责业务配置和用户体验；两者通过版本化的 t1bridge ABI 连接。

## 1. 目标边界

最终只保留一个 T1 专用内核驱动服务 `T1RemoteFilter`。同一个 `t1filter.sys` 可以分别附着到 T1 的多个 HID Collection，`COL02` 和 `COL03` 不是两个驱动。

HidHide 只作为当前验证阶段的临时保护措施。等 T1RemoteFilter 能稳定完成报文拦截、丢弃和改写后，正式方案不再依赖 HidHide。

驱动需要保证：

- 只处理 VID=0x620A、PID=0x0407 的 T1 HID 子设备；
- 普通键盘、鼠标和其他蓝牙设备不进入 T1 策略；
- Python 进程退出、崩溃或设备断开时，不留下粘键和永久吞键状态；
- 驱动升级失败时，设备可以回退到 Windows 原生透传；
- 未确认的报文默认不改写、不注入、不模拟。

驱动不负责：

- Home、音量、Power 等业务名称和最终键位配置；
- 双击、长按、组合键、宏、应用快捷键和按应用切换配置；
- Google 语音调用、GATT 音频协议、ADPCM 解码和虚拟麦克风；
- Tkinter 界面、配置文件和用户权限管理界面。

## 2. 必须放进驱动的能力

| 能力 | 作用 | 优先级 |
| --- | --- | --- |
| 精确设备匹配 | 只挂载到 T1 目标 HID Collection，隔离其他输入设备 | P0 |
| 完整 HID 请求路径 | 覆盖普通 DeviceControl、InternalDeviceControl 和实际 UMDF HID 输入路径 | P0 |
| 原始报文截获 | 在 HIDClass 解释前复制报文，提供 Usage Page、Collection、Report ID 和时间序列 | P0 |
| 报文丢弃 | 命中策略后清零或替换输入报文，阻止 Windows 继续处理 | P0 |
| 报文改写 | 在安全的字段范围内修改 Usage 或按位字段，支持按键重映射基础能力 | P1 |
| 运行时策略 | Python 下发、校验、原子替换和回滚拦截规则，不需要重装驱动 | P1 |
| 安全租约 | Python 定期心跳；心跳失效后自动回到透传或安全策略，避免应用崩溃后永久吞键 | P1 |
| 有界事件队列 | 固定容量环形队列、序号、时间戳、溢出计数和丢包统计 | P1 |
| 事件通知 | 支持阻塞读取或内核事件通知，逐步替代 Python 高频轮询 | P1 |
| PnP 生命周期 | 处理蓝牙重连、设备移除、重新枚举和驱动卸载 | P1 |
| 电源生命周期 | 处理睡眠、Modern Standby、唤醒和挂起中的未完成请求 | P1 |
| 诊断接口 | 返回已附着 Collection、请求路径、策略版本、报文计数、错误码和队列状态 | P1 |
| 版本与能力协商 | ABI 版本、驱动版本、最大报文长度和支持特性显式查询 | P1 |
| 取消与并发保护 | 正确处理 IRP 取消、设备拔出、策略更新和完成回调竞态 | P1 |
| 报文布局描述 | 支持 Report ID、字段位偏移、字段宽度、多键同时按下和不同 Collection 布局 | P2 |
| 自动恢复 | 驱动异常或桥接断开后清理状态，允许应用重新建立会话 | P2 |

## 3. 报文处理设计

驱动不能长期依赖固定的 `Report[1]`、`Report[2]` 字节位置。T1 当前的 `COL02` 和 `COL03` 可以作为验证夹具，但后续需要支持：

- Report ID 不同的 Collection；
- Consumer、System、Keyboard、Mouse 和 Vendor Defined 报文；
- 一个报文中多个 Usage 同时处于按下状态；
- 按位字段、数组字段和按键释放；
- 不同固件版本改变报告长度或字段布局。

推荐由 Python 读取并解析 Report Descriptor，生成经过校验的“字段规则表”，由驱动执行最后的边界检查和报文修改。这样驱动保持小，固件布局变化时不需要重新编译内核代码。

字段规则至少应包含：

- Collection 编号和 Usage Page；
- Report ID；
- 字段偏移、字段宽度和字段数量；
- 源 Usage、目标 Usage 或清零动作；
- 按下、释放和数组字段的处理方式。

驱动只允许修改规则表声明的字段，禁止 Python 传入任意指针、任意长度或任意设备路径。

## 4. 策略模式

驱动保留三种基础模式，业务模式由 Python 组合：

1. `Observe`：只统计和上报，不改变 Windows 输入，供调试和重新抓包。
2. `Intercept`：命中规则的报文进入事件队列，并从下游输入路径丢弃或清零。
3. `Remap`：命中规则的报文进入事件队列，同时按字段规则改写后继续传递。

还需要一个显式的 `DropUnmapped` 选项。它只在完成整套真实硬件回归后启用，用于确保遥控区域不会漏出到 Windows。默认配置保持保守，避免未知报文导致键盘或鼠标失效。

策略更新必须满足：

- 固定 ABI 和长度校验；
- 单次原子替换，不出现半张策略表；
- 拒绝重复源 Usage 和越界字段；
- 新策略失败时保留旧策略；
- STOP、设备断开和租约超时清理活动 Usage。

## 5. 必须留在 Python 的能力

以下能力放在 Python 更合适，驱动只上报标准化事件：

- 单击、双击、长按、连按和按住重复；
- 多键组合、宏和应用快捷键；
- 浏览器、媒体播放器、会议软件等应用动作；
- 每应用配置、配置导入导出和界面编辑；
- Air Mouse 的光标速度、加速度和手势；
- GATT 服务发现、语音协议协商和音频解码；
- WASAPI 输出、虚拟麦克风选择和录音设备状态。

T1 麦克风不要并入 HID 驱动。它属于 BLE GATT 音频链路；只有在产品必须提供系统级虚拟麦克风且用户态方案不可用时，才单独评估音频驱动。

## 6. 安装和升级边界

正式包包含一个 `t1filter.sys`、一个 INF/CAT 和用户态 `t1bridge.dll`。Python 不直接加载内核模块，只调用桥接 DLL。

开发阶段仍使用测试签名。正式发布前需要：

- 正式代码签名和驱动签名策略；
- 安装前检查 Secure Boot、系统版本和架构；
- 安装、升级、回滚和卸载流程；
- 驱动包版本与 ABI 版本分离；
- 内核模块已被占用时明确提示重启，不强行覆盖正在运行的镜像。

驱动安装器不应自动修改全局 HID Class 过滤器，也不应依赖 HidHide 的应用白名单。

## 7. 分阶段执行顺序

### P0：先完成当前拦截闭环

- 修复 `EvtDeviceAdd`，确认 T1 两个 Collection 真正出现 `T1RemoteFilter`；
- 让 `GET_CAPABILITIES`、`GET_STATS` 和事件读取返回一致结果；
- Home、Volume、Voice 做按下/释放真机回归；
- Power 只做驱动事件和系统日志验证，不重复触发真实关机/睡眠；
- 在未使用 HidHide 的情况下确认 Windows 不再收到被拦截键。

### P1：补齐可长期运行的驱动基础

- 增加租约/心跳和安全回退；
- 增加 PnP、蓝牙重连、睡眠恢复和请求取消处理；
- 增加 attached Collection、请求路径和计数器诊断；
- 将轮询读取升级为可等待事件；
- 统一 COL02、COL03，并为 COL01、COL04、COL05 保留受控扩展入口。

### P2：完善通用 HID 报文能力

- 接入 Report Descriptor 和字段规则表；
- 支持多 Usage、位字段和不同 Report ID；
- 完成报文重映射和 DropUnmapped 的回归测试；
- 验证 Air Mouse 的按钮屏蔽与鼠标移动透传边界。

### P3：产品化

- Python 配置、托盘、日志和诊断页面；
- 安装器、签名、回滚和版本检查；
- 移除 HidHide，并保留驱动未安装时的 Observe 模式；
- 完成 Windows 10/11 x64、重连、睡眠、应用崩溃和异常断电测试。

### P4：语音链路

- 单独验证 `AB5E0001` GATT 服务和特征；
- 确认音频编码、采样率、帧长和结束条件；
- 用户态完成解码和音频端点输出；
- 只有用户态无法提供系统麦克风端点时，才单独设计音频驱动。

## 8. 当前不应加入驱动的功能

- Google 账号、网络请求和云端语音调用；
- JSON 业务配置解析；
- 应用窗口识别和全局快捷键逻辑；
- 宏执行、脚本执行和任意进程注入；
- 鼠标轨迹滤波和语音降噪；
- 为了减少一次重启而引入的全局 HID Hook 或未签名组件。

## 9. 验收标准

驱动阶段完成的判定条件：

- T1 `COL02/COL03` 的设备栈明确包含 `T1RemoteFilter`；
- Home、Volume、Voice 的原始事件可被 Python 读到，Windows 不再执行默认动作；
- Power 事件可以被驱动统计和阻断，测试不触发实际睡眠；
- 普通键盘、鼠标和其他蓝牙设备不受影响；
- T1 断开、重连、睡眠恢复后不残留按键状态；
- Python 崩溃或退出后，驱动按租约策略回退，不永久吞键；
- 驱动未安装、版本不匹配或策略非法时，应用明确进入 Observe/不可用状态。


# T1 Remote 产品信息梳理

## 资料范围

本梳理基于 `Docs/product` 下的 4 张产品资料截图，以及当前 Windows 主机对 `T1-Remote` 的设备枚举结果。截图未提供明确品牌、正式型号、HID Report Descriptor 或通信协议，因此项目暂按 `T1 / T1-Remote` 作为产品标识。

## 产品定位

T1 是一款面向电视、盒子或大屏设备的多功能无线遥控器，集成：

- 蓝牙无线连接；
- 2.4G 无线连接；
- 红外遥控和红外学习；
- 空中鼠标/体感鼠标；
- 双面无线键盘；
- Google Voice Assistant 语音功能；
- 自动识别正反面并屏蔽另一面的智能控制。

## 产品资料中明确的功能

### 连接方式

| 功能 | 资料描述 | 对 Windows 项目的含义 |
| --- | --- | --- |
| Bluetooth | 有效距离最高 10 米 | 当前已确认 Windows 侧以 BLE HID 设备出现 |
| 2.4G | 有效距离最高 10 米 | 需要插入接收器后单独确认是否为标准 HID |
| Infrared | 红外遥控、支持红外学习 | 主要面向被控家电，不属于 Windows HID 改键基础路径 |

### 遥控器正面按键

图片标注了以下按键或区域：

- Power；
- 方向环和 OK；
- Return；
- Mute；
- Voice；
- Home；
- Menu；
- Volume Plus；
- Volume Minus；
- 一个用于开启飞鼠功能的 `Air Mouse` 按键；
- Indicator light。

根据“ A 面 12 个按键和 2 个侧键”的规格，遥控区域可按 14 个实体按键计算：正面 12 个，侧面音量加减 2 个。方向环按上、下、左、右 4 个方向键加中心 OK 键拆分。`Air Mouse` 用于开启飞鼠功能，采集阶段禁用；Power 由驱动层拦截后采集。

本轮采集只针对这 14 个遥控区域按键。键盘面 45 个按键、Fn 组合和键盘面的方向/Home 等按键暂不采集。Air Mouse 开启后的连续鼠标移动报文也暂不纳入本轮按键采集。

### 键盘面

资料描述为 59 键无线键盘。规格页写有：

- A 面：12 个按键和 2 个侧键；
- B 面：45 个按键；
- 合计 59 键。

键盘图中可见字母、数字、功能键、修饰键、方向键、Home、Page Up、Page Down、End、Delete、Enter、Back、空格等按键。具体每个按键在 T1 HID 报文中的 Usage 必须通过真实采集确认。

### 鼠标和智能控制

- 支持体感/空中鼠标功能；
- 资料描述为即时响应；
- 能自动识别当前使用的正面，并自动屏蔽另一面输入。

Windows 项目需要区分鼠标 Collection、键盘 Collection 和 Consumer Control Collection，不能把空中鼠标移动或点击误识别为普通遥控器按键。

### 语音功能

- 产品资料标注 Google Voice Assistant；
- 语音采样率标注为 16K；
- 资料宣称 16K 采样率有利于识别效果。

当前设备还枚举出 `AB5E0001-5A21-4F05-BC7D-AF01F617B664` GATT 服务。这与参考项目的 ATVV 服务线索一致，但仍需确认 T1 的特征、能力协商、音频帧和编码是否兼容，不能只凭服务 UUID 直接复用完整语音链路。

## 本次 Windows 项目应覆盖的产品能力

### 第一阶段：遥控区域 HID 采集和诊断

- 识别 `T1-Remote` 及 `VID=0x620A / PID=0x0407`；
- 区分键盘、Consumer Control、鼠标和 Vendor Defined Collection；
- 只记录 14 个遥控区域按键触发的原始 Report；
- 逐个确认按下、释放、重复和长按行为；
- 记录按键所属 Collection、Usage Page、Usage 和原始 Report；
- 暂不对键盘面按键、Fn 组合和空中鼠标移动做映射；
- 设备断开、休眠、重连和应用退出时结束采集并释放状态。

### 第二阶段：语音输入

- 验证 T1 Voice 键的按住/释放语义；
- 验证 `AB5E0001` 服务及其音频特征；
- 验证 16 kHz 音频帧、编码、能力协商和结束排空；
- 选择 Windows 音频输出端点或虚拟麦克风方案；
- 语音功能失败时不能影响普通 HID 按键映射。

### 第三阶段：2.4G 接收器和完整产品适配

- 确认 2.4G 接收器是否枚举为标准 HID；
- 如果是标准 HID，复用 T1 映射引擎；
- 如果是私有协议，单独建立接收器协议适配，不与 BLE HID 逻辑混在一起；
- 评估自动识别蓝牙模式和 2.4G 模式下的同一物理按键。

## 暂不纳入 Windows 基础项目

- 红外码学习和红外发射控制；
- 修改 T1 固件；
- 未经确认的 Vendor Defined 报文写入；
- 需要内核驱动或管理员权限的强制吞键方案；
- 把宣传资料中的“即时响应”“高识别率”直接当成可验收的软件指标。

## 关键验证项

1. 14 个遥控区域按键是否逐个产生稳定的按下、释放 Report。
2. 遥控器面按键是否分布在 Keyboard、Consumer Control、Mouse 或 Vendor Defined Collection。
3. 方向环是否分别产生上、下、左、右四种事件，中心是否独立产生 OK 事件。
4. Air Mouse 开启飞鼠后，Mouse Collection 报文如何映射为 PC 鼠标移动和按键。
5. Voice 键是 HID 触发、GATT 触发，还是同时触发两条链路。
6. T1 休眠、唤醒、断连和重连后是否会残留按下状态。

## 项目结论

本次项目的目标产品应定义为：

> 适配 T1-Remote 的 Windows 多功能遥控器助手，优先提供设备级 HID 识别、按键重映射和诊断，再扩展语音与 2.4G 模式支持。

产品资料支持功能范围判断，不能替代协议和按键报文验证。下一步开发应以 T1 HID Inspector 采集结果为依据。
